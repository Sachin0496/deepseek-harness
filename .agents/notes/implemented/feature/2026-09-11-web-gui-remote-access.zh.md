# Agent Note：Web GUI 的远程访问

Status: implemented

[English](2026-09-11-web-gui-remote-access.md) | 中文

## 问题

Web GUI 只服务一台机器。`dsh web` 绑定 `127.0.0.1` 并打印一个带令牌的 URL，只有该机器上的浏览器能打开；而唯一有文档记载的跨设备访问方式——`--host 0.0.0.0`——在启动时就被拒绝，因为裸的全接口绑定会把未经认证的远程代码执行暴露到网络上。想用手机在另一个网络里向会话发指令的用户没有受支持的途径：SSH 端口转发需要手机上装客户端，而 `resolveLanTrust` 推导出的 LAN URL 只存在于 CLI 所拒绝的全接口绑定之下。

摩擦并不在 URL 本身，而在它周围的一切。即便有了可达地址，用户仍须把一个四百多字符、带令牌的 URL 誊写到手机上；而 `/api` 栅栏会拒绝任何部署在绑定之前未曾声明的 Host 权威。

## 决策

`dsh web` 新增 `--remote`：通过 Cloudflare 快速隧道把回环监听发布到公网，并打印公网 URL 与终端二维码。

`--remote` 不改变绑定。连接器拨号 `http://127.0.0.1:<port>`，因此进程仍然只服务回环，公网一侧由隧道的 TLS 端点终结。这保住了 `--host 0.0.0.0` 的拒绝而非削弱它：原始端口从不暴露，唯一的公网入口是带认证边缘的 HTTPS 源。

隧道的公网主机名在连接时才被分配，因此任何组合期配置都无法携带它。`HostConnectionService.addTrustedAuthority(authority)` 在运行时扩展既有 `/api` 栅栏，并返回撤销用的 disposer。新增路径会运行 `assertTrustedAuthority`——与配置边界相同的校验——因此畸形条目在调用处抛错，而不是悄悄放大授权；新增的权威随后面对与已配置权威完全相同的 Host/Origin 与浏览器会话规则，不是更弱的层级。Client 侧的 `trustedHosts` 仍是构造值；运行时集合只存在于 Host 服务中。

`src/remote-access.ts` 负责连接器。`startQuickTunnel` 在连接器打印出所分配主机名、再经过一段发布宽限期之后才 resolve；每条失败路径——可执行文件缺失、提前退出、超时——都在 reject 之前停掉连接器。启动失败会在 stderr 上报告，运行继续以回环方式服务：丢失公网 URL 不应以本地会话为代价。

### 等待而不毒化运维者的 DNS

连接器打印主机名时，Cloudflare 还没有该主机名的边缘记录——实测为 3-5 秒——因此在这一刻显示的二维码扫出来是浏览器的 `DNS address could not be found` 页面。显而易见的修法——轮询该源直到它应答——比这个缺陷更糟。`trycloudflare.com` 的否定 TTL 是 **1800 秒**，因此在记录存在之前发出的查询会被运维者自己的解析器缓存为 NXDOMAIN，并在它所错误否认的记录之后仍然存续。针对实时隧道所做的对照实验区分了两条路径：

| 轮询路径 | 之后运维者的解析器 | 运维者机器上的 HTTPS |
|---|---|---|
| `dns.lookup`（浏览器所用的系统路径） | `ENOTFOUND`——已被毒化 | 失败 |
| 直接查询公共解析器 | 正常解析 | 返回 `401` |

因此经系统解析器轮询不只是帮不上忙；它会让启动它的那台机器在长达半小时内连不上该隧道，而且重启也无法清除。`startQuickTunnel` 因此绝不解析公网名称：它把已发布的 URL 保留 `publicationGraceMs`（默认 8 秒，覆盖实测间隔）之后再报告。两件事被分开：发布是连接器的成功，可解析性属于 Cloudflare；一个可能破坏运维者环境的探测，不能成为让该特性工作的手段。

在宽限期内退出的连接器仍然 reject：它的隧道已经消失，交出它的 URL 只会误导。

URL 就是凭据。它携带与回环 URL 相同的进程级启动令牌，因此 `--remote` 改变的是可达性，不是授权。令牌按进程铸造且从不持久化，这正是让这个无认证边缘可接受的原因：公网主机名随机且短命，其背后守护会话的只有运维者掌握的密钥。

### 运维者看到的内容

```
dsh web: http://127.0.0.1:3080/?token=…
dsh web: publishing through a Cloudflare quick tunnel; this takes a few seconds
dsh web: remote https://<assigned>.trycloudflare.com/?token=…
dsh web: that URL is the credential for this session; anyone holding it can drive it
<QR code>
dsh web: scan to open this session on another device
```

`--no-qr` 抑制二维码；`--cloudflared <path>` 指定 `PATH` 之外的连接器。这些行在发布宽限期之后出现，因此显示出来的 URL 已是可扫描的。

## 曾考虑的替代方案

**复用 `--host 0.0.0.0` 加上受信主机。** LAN 路径已存在且无需依赖，但无法满足既定需求：蜂窝网络上的手机无法路由到私有 LAN 地址，而且该绑定在无 TLS 的情况下暴露原始端口。它还与 CLI 在其自身错误文本中明确声明的拒绝相矛盾。

**在一个标志后面同时支持 Tailscale、ngrok 和 cloudflared。** 机器上已安装 Tailscale，它本可提供带稳定 URL 的私有网状网络，是更安全的姿态。它败给了用户既定目标所要求的配置成本：它需要在 Mac 和手机上分别登录，第一次扫码才能工作；而快速隧道两侧都不需要账号。只选一种传输也让失败报告保持单一形态。

**在进程内实现隧道协议，而不是派生连接器。** 这会消除外部依赖与子进程生命周期。它败给了成本：实现 WireGuard 与 Cloudflare 边缘握手是一大片安全攸关的表面，而一个受维护的二进制已经拥有它；本仓库在维护良好的依赖能真正删除自有代码与测试时，也偏好依赖而非手写。

**手写二维码编码器。** 这能省掉一个依赖。它败给了 `uqr`（纯 ESM、零依赖、在源码启动的 tsx 约定下没有 CJS 隐患），因为二维码编码器是没有产品特有行为的算术，而 `renderUnicodeCompact` 正是所需的终端形态。

**为回环或 LAN URL 打印二维码。** 这能完全避开隧道。它败给了可达性：两个地址都无法从另一个网络访问，扫出来的码在手机上也打不开。

## 后果

远程访问不需要端口转发、不需要账号、不需要在手机装客户端，而且手机通过真实 HTTPS 抵达会话，这也给了浏览器安全上下文——明文 HTTP 的 LAN 源给不了。

代价真实且出于有意。快速隧道是公开的：任何拿到 URL 的人都能驱动会话，因此运维者必须把二维码当作密钥对待。Cloudflare 每次启动都分配新主机名，所以一个 URL 只对一次运行有效，无法跨重启收藏。TLS 终结的公网权威收到的 cookie 依然不带 `Secure`，因为同一个进程同时服务回环与公网两个权威。连接器自身的可用性界定了这一特性：它必须已安装，而封锁隧道的网络只留下回环 URL。

扫描是一次跨站导航，会话 cookie 的属性必须容许它：浏览器在浏览上下文之外把扫到的 URL 交给新页面，因此[浏览器会话 cookie](../architecture/2026-08-24-browser-token-authentication.zh.md)取 `SameSite=Lax`。在原先的 `Strict` 下，浏览器存下了签发的 cookie，却不在跳转到干净 `/` 的 `303` 上发送它，于是每次扫描正确的码都停在 401 页面。`Lax` 对整个进程的 cookie 一律生效，回环也在内，因为同一进程服务两个权威。

想要更强控制的部署，应当用自带认证的隧道或反向代理挡住回环监听，并用 `--trusted-host` 声明那个稳定主机名——这无需改动本代码。

## 测试

`tests/remote-access.spec.ts` 通过伪造的子进程驱动连接器生命周期——从任一流捕获源、可执行文件缺失／提前退出／超时三类失败、启动后退出上报、幂等关闭——因此没有测试需要该二进制或网络。它还固定发布宽限期：URL 在宽限期结束前不交出、结束后无论如何交出、连接器在期内退出则 reject，且随后的输出行无法替换已发布的源。`tests/web-app-remote.spec.ts` 覆盖运行时的发布、栅栏准入、释放，以及必须让本地服务继续运行的那条隧道失败路径。`tests/node-half.host.spec.ts` 覆盖 `addTrustedAuthority`：未声明的权威在注册前返回 403，新增权威在无会话时到达 401、有会话时通过，撤销后恢复 403，畸形条目抛错。

端到端路径已在真实快速隧道上验证：令牌交换在公网源上返回 303 并铸出 cookie，带该 cookie 的索引返回 200，未认证请求返回 401，点名隧道 Host 的请求抵达 RPC 桥，而未声明的 Host 返回 403。

就绪行为只能对真实基础设施观测，因此在那里定论而非放在单元测试里。一个驱动脚本启动 `dsh web --remote`，捕获远程 URL 打印的那一刻，并在同一刻检查系统解析器与 HTTPS：宽限期之前系统解析器返回 `ENOTFOUND`，而记录其实已经公开；加入宽限期之后解析器正常应答，HTTPS 返回 401。上面的 DNS 毒化对照针对实时隧道跑了两条轮询路径，并记录各自之后运维者解析器的状态。随后由真实 Chromium 模拟扫码——外部源上的页面交接该 URL，也就是相机应用的行为——在干净的根 URL 上渲染出 GUI，地址栏中不残留令牌。
